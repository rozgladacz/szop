## Kandydaci ZWERYFIKOWANI (przeczytane, oceniony engineering)

### roster_adapter — schema match + defensywne defaulty

- **Engine-dict schema zgodny.** Klucze produkowane przez `roster_to_engine_roster`
  (`owner_player`, `units[].{id,position,models,toughness,quality,defense,passives,weapons}`
  + `weapons[].{slug,name,range_inches,attacks,ap,weapon_abilities}`) odpowiadają
  1:1 konsumpcji w `state.build_initial_state` (`state.py:281-345`): partycja broni
  po `range_inches`, `is_hero = "bohater" in passives`, walidacja `passives` przeciw
  `excluded_slugs`. Brak rozbieżności kontraktu.
- **`int(getattr(unit,"quality",4))` bez `or` to NIE crash na NULL.** `quality`,
  `defense`, `toughness` są `nullable=False` (`models.py:326-328`);
  `typical_model_count` to property zwracające zawsze `int≥1` (`models.py:357-365`,
  try/except + clamp). Default w `getattr` to belt-and-suspenders, nieosiągalny w
  praktyce → brak `TypeError(int(None))`.
- **Filtr exclusions vs INCOMPLETE spójny z engine.** `dropped_excluded` usuwa slugi
  z `b_mvp_exclusions` PRZED przekazaniem (inaczej `UnsupportedAbilityError`),
  `inert_incomplete` przepuszcza (engine cicho ignoruje) — dokładnie kontrakt
  `state.py:284-294`. Dedup raportów (`if slug not in ...`) poprawny.
- **`_PLAYER_ID_STRIDE=10_000`** rozłącza przestrzenie id blobów owner 0/1; realnie
  ≤ kilkanaście blobów/gracz → brak kolizji id w `BattleState`.
- **`_unit_weapons` primary-first** — sort stabilny (`0 if primary else 1`) po dedup
  `(slug,range_inches)`; engine MVP używa `melee_weapons[0]`/`ranged_weapons[0]`,
  więc primary musi być pierwsza per kategoria. Tożsamość przez `id(weapon)` (nie
  `weapon_id`) bo transient ORM bez FK przed flush — poprawne dla efemerycznych
  rosterów z exploit_hunt.

### exploit_hunt — reuse SSOT + determinizm + degradacja

- **Promień kandydata = mirror wzoru silnika.** `unit_deploy_radius` liczy
  `tou_sum = typical×toughness/(2 if hero else 1)` → `compute_radius_inches`
  (reuse SSOT, ADR-0008), identycznie jak `state.py:298-299` dla `per_copy`
  (blob = 1 kopia = `typical` modeli). Filtr `≤ 6″` (½ krótszego boku strefy 72×12)
  zapobiega `IllegalActionError` w fazie rozstawienia.
- **Fairness self-play** — mapa `lustrzana_a` (mirror y=24), naprzemienna inicjatywa
  (`initiative_for_game(i)`), rozłączne seedy graczy (`+PLAYER_SEED_OFFSET`) i par
  (`pair_seed += n`). owner 0/1 nie zamieniają stron, ale mirror map to neutralizuje.
- **Determinizm** — pojedynczy `random.Random(args.seed)` zasila generator;
  `simulate_from_rosters(seed=...)` + rozłączne rng graczy → bit-deterministyczne.
- **Łagodna degradacja na pustej bazie** — `len(candidates)<1` → exit 1 + czytelny
  komunikat (sprawdzone smoke; dev DB ma 0 `Unit`). DB read-only (`SessionLocal()`
  context, brak write). `_load_balance_simulate` (import sąsiedniego skryptu) wzorzec
  jak `battle_replay.py`, idempotentny przez `sys.modules` cache.
- **`exploit_score`/`win_rate`** strzeżone przed dziel/0 (`if self.points>0`,
  `if self.games`). `format_report` `scores[:max(top,0)]` bezpieczne dla `top≤0`.

## Drobne obserwacje (nie findingi, nie naprawiane)

1. **Efficiency O(n²) generator (niski, JUŻ ŚLEDZONY):**
   `generate_random_roster` przebudowuje transient roster i przelicza
   `roster_points` w KAŻDEJ iteracji pętli `while` → kwadratowo względem liczby
   dorzucanych kopii (≤8). Jawnie zalogowany jako follow-up w commicie `32919b9`
   (`HANDOFF_faza-d-exploit-hunt`). `n` małe → bez wpływu praktycznego. Nie
   duplikuję jako nowy finding.
2. **Weapon dedup vs primary (bardzo niski, edge):** `_unit_weapons` dedupuje po
   `(slug, range_inches)` PRZED sortem primary-first, zachowując PIERWSZY wpis z
   `default_weapon_loadout`. Gdyby broń non-primary o tym samym slug+range
   poprzedzała primary w loadoucie, przetrwałby wpis non-primary (jego attacks/ap).
   Wymaga dwóch broni o identycznym znormalizowanym slug i zasięgu różniących się
   tylko statami — rzadkie; engine i tak używa tylko pierwszej broni per kategoria.
   Nie naprawiane (poszerzyłoby kontrakt; brak realnego triggera w danych).
3. **owner 0/1 stała strona (by design):** rozpiski nie zamieniają stref top/bottom
   między grami; neutralizowane przez mapę lustrzaną. Gdyby dodano mapy
   niesymetryczne — wymagałoby swap stron. Poza MVP.
