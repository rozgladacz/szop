## Kandydaci ZWERYFIKOWANI (przeczytane, oceniony engineering)

Punkty, które finder/analiza podniosła, a weryfikacja **odrzuciła** (REFUTED) lub
oceniła jako by-design — z dowodem z kodu:

1. **Dzielenie przez zero przy pełnym odfiltrowaniu pary (`--max-imbalance`):**
   gdy roster zostaje wyłączony ze WSZYSTKICH par, `games[i]=0`. **Bezpieczne** —
   `RosterScore.win_rate` ma guard `self.wins / self.games if self.games else 0.0`,
   `exploit_score` guard `points > 0`. `cost_delta_pct`/filtr mają guard `mean > 0`.
2. **Stabilność seedów per para vs filtr:** `seed_ab = base_seed + pair_ordinal*n`
   liczony PRZED `continue` filtra dysbalansu → strumienie gier niezależne od tego,
   ile par odpadło (zweryfikowane testem `test_exploit_hunt.py:268-290`). OK.
3. **`rng.choice` z pustej puli w trybie distinct:** ścieżka
   `[u for u in pool if id(u) not in counts]` mogłaby być pusta tylko gdy
   `len(counts) >= len(pool)`, ale `want_distinct = min(min_distinct, len(pool), …)`
   gwarantuje `len(counts) < want_distinct ≤ len(pool)` → zawsze ≥1 nieużyty. OK.
4. **Semantyka per-model vs total liczby broni:** `_default_loadout_payload` zapisuje
   `default_count` jako wartość per-model; `calculate_roster_unit_quote` (`_yaml_quote`
   l.188) mnoży `stored_count * model_count` (mode≠"total"). Zgodne z traktowaniem
   w `rosters._default_loadout_payload` (router). Brak rozjazdu.
5. **Zmiana sygnatury `run_tournament` (zwraca krotkę):** wszyscy pozostali
   wywołujący (`tests/*`) używają default `return_pairs=False` → dostają listę jak
   wcześniej; `main()` jawnie rozpakowuje. Wsteczna kompat zachowana.
