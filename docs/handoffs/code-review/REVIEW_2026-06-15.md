- **Brak osieroconego `.melee_balance` w żywym kodzie.** Grep całego repo:
  każde pozostałe trafienie `melee_balance` w `app/**` to docstring/komentarz
  objaśniający rename (`events.py` docstring `MeleeBalanceReset`, `state.py`
  komentarz pola). Zero `blob.melee_balance` / `replace(..., melee_balance=...)`
  / klucza dict / kolumny ORM / serializera / frontend JS / YAML.
- **Jedna definicja pola** — `state.py:178` `damage_balance: int = 0`, brak aliasu
  ani drugiej definicji. Brak ścieżki blob→dict, która zciekłaby starą nazwę.
- **Reducer:** `@register_reducer("MeleeBalanceReset")` zarejestrowany dokładnie
  raz ([reducers.py:221](app/services/engine/reducers.py:221)); handler
  `_reduce_damage_balance_reset` czyta `blob.damage_balance == 0` i pisze
  `replace(blob, damage_balance=0)` — read i write na tym samym (nowym) polu.
- **Spójny read+write na 4 call-site'ach:** `_reduce_melee_resolved`
  (reducers.py 142–163), `resolve_melee_attack` (combat.py 593–595), regroup

  starego/nowego pola.

### Blok B5 (LocalClient) — wierny, cienki wrapper

- **Numeracja sekwencji bez off-by-one.** `create_battle` ustawia
  `next_sequence = len(deploy_events) + 1`. `deployment_round` numeruje eventy
  kontiguicznie `1..k` (jeden licznik `seq`, +1 per `MoveExecuted`/`StatusAdded`,
  reset AKTYWOWANY nie emituje), więc `len(deploy_events) == k` i `+1` to poprawna
  pierwsza sekwencja akcji. Dokładnie to asertuje `test_take_action_matches_resolver`.
- **`take_action` threading poprawny** — `record.next_sequence` in,
  `result.next_sequence` out; `record.events.extend(result.events)` kopiuje z
  immutable tuple (brak aliasingu); `_BattleRecord.events` init przez
  `list(deploy_events)` (świeża kopia).
- **`get_events` granica** — `e.sequence > since` (strict): `since=0` → wszystko
  (sekwencje od 1), `since=last_seq` → `()`. Test-potwierdzone.
- **`simulate` agregacja** — `wins[result.winner]` indeksowane per `owner_player`
  (0/1), `None` → draw; `seed=seed+i`, `init=(i%2)` przy `alternate_initiative`,
  świeży `player_factory(i)` per grę — bit-identyczne z `simulate_balance`
  (parity test zielony).
- **Walidacja błędów** — `n<=0` → `ValueError`; nieznane `battle_id` →
  `UnknownBattleError(KeyError)`. Pokryte.

**Drobna obserwacja (nie finding):** gałąź `alternate_initiative=False`
(`init=initiative_player`) nie ma osobnego testu — logicznie trywialna i poprawna.
