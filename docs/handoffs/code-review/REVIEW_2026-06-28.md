## Findings

**Bugi korektności (crash/zła-wartość na ścieżce normalnej): 0.**

Zweryfikowane i ZGODNE (8 kątów: line-by-line, removed-behavior, cross-file,
reuse, simplification, efficiency, altitude, conventions):

- **Surowy token nie wycieka.** `create` zwraca `token` tylko przez
  `AgentTokenCreated`; `list`/`revoke` mają `response_model=AgentTokenPublic`
  (bez pola `token`). Do DB idzie wyłącznie `hash_agent_token(raw)`; audyt
  (`params_json`) zawiera scope + action, nie token. Potwierdzone testami
  (`response.token not in stored.token_hash`, `... not in audit[0].params_json`).
- **Spójność strefy czasu.** `_now()` = `datetime.now(UTC).replace(tzinfo=None)`
  — naiwny UTC, identycznie jak `security._authenticate_agent` (porównanie
  `expires_at <= now`). Brak mismatch aware/naive na ścieżce wygaśnięcia.
- **Regex scope bezpieczny.** `^(?:\*|[a-z][a-z0-9_.:-]{0,63})$` + `fullmatch`
  → odrzuca wielkie litery, spacje i trailing `\n` (fullmatch nie domyka po `$`).
  Kwantyfikator ograniczony `{0,63}`, brak zagnieżdżenia → brak ReDoS.
- **Wildcard-exclusivity i dedup.** `_validate_scopes` dedupuje z zachowaniem
  kolejności i blokuje `["*", ...]`; round-trip `_scope_json`/`_scopes_from_json`
  stabilny (`sort_keys`). Zgodne z `security._parse_agent_scopes`/`_scope_allows`.
- **Revoke autoryzowany i idempotentny.** `WHERE id == ? AND owner_user_id == ?`
  → cudzy token = 404 (nie 403, brak enumeracji istnienia); drugi revoke nie
  nadpisuje `revoked_at` ani nie dubluje audytu. Potwierdzone testem.
- **Transakcja spójna.** `add_all` + `flush` (uzyskanie `agent_token.id` do
  audytu) → audyt → pojedynczy `commit`; przy kolizji `username`
  (unique) wyjątek propaguje, nic nie zostaje zacommitowane.
- **Brak duplikacji logiki.** Helpery scope są lokalną parą write-side do
  read-side z `security.py` (świadomie rozdzielone moduły) — nie ma istniejącego
  współdzielonego helpera do re-użycia. `hash_agent_token`/`hash_password`
  poprawnie importowane z `security`.
- **Convention (`__all__`/import).** Sprawdzono: istniejąca lista
  (`admin, armories, armies, …`) NIE jest ściśle alfabetyczna (armories przed
  armies), więc brak udokumentowanej reguły porządku → umieszczenie
  `agent_tokens` na początku nie jest naruszeniem. Nie zgłaszam.

### Backlog / obserwacje (low — NIE naprawione)

- **Brak limitu liczby tokenów/agentów per owner.** Każdy `POST /agent_tokens`
  wstawia nowy wiersz `User(role=agent)`; zalogowany użytkownik może utworzyć
  nieograniczoną liczbę agentów (wzrost zasobów, niskie ryzyko). Kandydat na
  rate-limit/quota — odnotowane w wątku C1, nie blokuje.
- **Redundancja walidacji.** `_validate_scopes` powtarza `len > _MAX_SCOPES`
  oraz „empty" już egzekwowane przez `Field(min_length=1, max_length=20)`.
  Świadoma defensywa (funkcja wołana też z testów z pominięciem pydantic) —
  zostawione bez zmian.
