## Co było w zakresie

Hardening wątku **faza-b-engine-mvp** (kontynuacja po C3 `validate_loadout`):
trzy standalone skrypty-liście czytające domyślną bazę otwierały `SessionLocal`
**bez** standardowego `init_db()`. Na lokalnej `data/szop.db` sprzed ostatnich
addytywnych migracji kończyło się to surowym tracebackiem SQLAlchemy zamiast
działania jak aplikacja po starcie.

1. **`scripts/db_bootstrap.py` — nowy wspólny helper.** Context manager
   `initialized_session()`: lazy `from app.db import SessionLocal, init_db`,
   `init_db()` → `with SessionLocal() as session: yield session`.
2. **Trzy skrypty DB-read** (`exploit_hunt`, `simulate_engagement`,
   `validate_loadout`) zamieniają inline `from app.db import SessionLocal` w
   `main()` na `with initialized_session() as session:`.
3. **Testy CLI** — nowy helper `_patch_cli_db(monkeypatch, sm)` patchuje
   jednocześnie `app.db.init_db` (no-op/licznik) i `app.db.SessionLocal`
   (seeded in-memory). Regresja `assert init_calls == ["init"]` pinuje, że
   `main()` woła bootstrap, a testy nadal nie dotykają `data/szop.db`.

## Findings

**Bugi korektności (crash/zła-wartość na ścieżce normalnej): 0.**

Zweryfikowane i ZGODNE:

- **Patch trafia w cel.** Helper importuje `SessionLocal`/`init_db` z `app.db`
  dopiero w czasie wywołania, więc `monkeypatch.setattr("app.db.init_db", …)` /
  `"app.db.SessionLocal"` skutecznie podmieniają oba symbole. Potwierdzone
  zielonym `assert init_calls == ["init"]` we wszystkich trzech zestawach.
- **Brak wycieku sesji / poprawna propagacja wyjątków.** `@contextmanager` owija
  `with SessionLocal() as session: yield`, więc `session.close()` wykona się i na
  wyjątku. `init_db()` jest przed wejściem w kontekst sesji — gdyby rzucił, sesja
  nie jest jeszcze otwarta. OK.
- **Idempotencja side-effectu.** `init_db()` jest strażnikowany na każdym etapie
  (seed kopiowany tylko gdy plik DB nie istnieje; admin/ruleset/armory/weapons
  tworzone tylko gdy brak; `_migrate_schema` per-kolumna). Wielokrotne
  uruchomienie CLI nie duplikuje danych — zgodne ze startupem `app.main`.
- **Testy izolują lokalną bazę.** `init_db` patchowany na no-op → realny seed/
  migracje nie ruszają `data/szop.db`; schemat dostarcza seeded in-memory `sm`.
