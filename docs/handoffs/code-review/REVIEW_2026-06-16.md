## Kandydaci ZWERYFIKOWANI (przeczytane, oceniony engineering)

### Blok B6 (replay) — czysty, defensywny

- **`_fmt_melee` `if e.charger_id` to NIE falsy-zero bug.** `events.py:83`
  deklaruje `charger_id: int = 0  # 0 = nieustalone / kontratak; >0 = szarżujący`
  — `0` jest świadomym sentinelem, więc `if e.charger_id` (Szarża dla >0,
  Kontratak dla 0) wiernie odwzorowuje konwencję silnika. Spójne z resztą
  formatterów, które dla pól nullowalnych poprawnie używają `is not None`
  (`by_attacker_id`, `source_unit_id`, `previous_controller`).
- **`format_event` fallback** (`repr` dla nieznanej klasy) — nie crashuje na
  nowym typie eventu. Dobra higiena forward-compat.
- **`render_battle_log` inferencja zwycięzcy** (`p0>p1 ... else None`) identyczna
  z `match._winner` (pkt 5.f); używana tylko w `--from-db` (sim podaje
  `winner=result.winner` jawnie).
- **`replay_from_db`** — kolejność importu `app.models` przed `app.db` (cykl
  Base) udokumentowana; `create_all` idempotentne/addytywne → łagodna degradacja
  do "(brak eventów)". Read-only.

### Blok D5 (deployment) — spójny, warstwa-liść

- **`grid_deployment_position` — brak index/empty errorów na ścieżce wołającej.**
  `_build_deployment_from_players` woła go tylko dla blobów `models_alive>0 &&
  FRONT`, więc filtr `own` jest niepusty (sam unit kwalifikuje się) → `max(...)`
  i `next(...)` bezpieczne. `grid_positions(zone, len(own), max_radius)` zwraca
  dokładnie `len(own)` punktów → `idx ∈ [0, len(own)-1]`, brak IndexError.
- **Spójność filtra FRONT** — `_build_deployment_from_players` i
  `grid_deployment_position` filtrują identycznie (`FRONT && alive`), a setup
  kieruje zasadzka/rezerwa do ZAPLECZE (`state.py:327`) → rezerwy pomijane w obu
  miejscach spójnie (pkt 26, mid-game poza MVP).
- **Grid liczony dla `max_radius`** — koło największego oddziału mieści się w
  strefie, więc każde mniejsze też; walidacja per-unit `contains_circle` z `eps`
  toleruje pozycje na krawędzi `_usable_bounds` (`lo+radius`). Brak rozbieżności.
- **`_usable_bounds` degeneracja** (strefa < 2·radius → `lo==hi==mid`) świadomie
  nie rzuca — `contains_circle` odrzuci za wąską strefę z jasnym
  `IllegalActionError`. `random_position_in_zone` korzysta z `uniform(a,a)==a`.
- **Replay-safety RandomPlayer** — `choose_deployment` ciągnie z `self._rng`
  (deterministyczny per seed, ADR-0012); deployment zużywa rng przed akcjami,
  każdy gracz ma własny rng → bit-deterministyczne.
- **MRO mixina** — `class Bot(GridDeploymentMixin, Player)`: mixin (plain object)
  przed ABC nadpisuje `choose_deployment`; `choose_action` (abstractmethod) nadal
  z konkretnej klasy → instancjowalne. Potwierdzone 371 zielonymi testami.
- **`run_match` continuation lambda** — `_p=player, _a=active` jako default-args
  unika late-binding closure bug. Threading `seq`/`state` przez `apply_activation`
  poprawny (jak B5).

## Drobne obserwacje (nie findingi, nie naprawiane)

1. **Efficiency O(n²) (niski wpływ):** `GridDeploymentMixin.choose_deployment`
   przelicza pełny grid (sort + `max` + `grid_positions`) dla KAŻDEGO oddziału w
   `_build_deployment_from_players` → kwadratowo względem liczby oddziałów. `n`
   jest małe (≤ kilkanaście), więc bez znaczenia praktycznego. Ewentualna
   optymalizacja (policz grid raz per gracz) zmieniłaby kontrakt mixina — poza
   "prostą bezpieczną naprawą", zostawione.
2. **Robustness (niski):** `simulate_from_rosters(deployment_zones=())` (pusta
   krotka, nie `None`) wpadłaby w `IndexError` w `deployment_zones[owner]` zamiast
   czytelnego błędu. Tylko `None` wyłącza auto-deployment; kontrakt to
   `(zone_p0, zone_p1)` (len≥2). Default `None`, więc realnie nieosiągalne bez
   błędu wołającego — nie dodaję walidacji, by nie poszerzać API.
3. **Kolizje jednostka–jednostka (by design):** grid/random nie wymuszają >1″
   między oddziałami (pkt 13.a) ani cechy Niedostępny (pkt 4.c.i) — jawnie
   odłożone do E4 w docstringach `deployment.py`. Nie bug.
