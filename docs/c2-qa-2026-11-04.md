## Znaleziona i naprawiona usterka

**P2 — nieatomowy pierwszy DDL migracji protokołu.** W domyślnym trybie legacy
sterownika sqlite3 samo `connection.begin()` SQLAlchemy nie wysyła fizycznego
`BEGIN` przed `CREATE TABLE`. Awaria kopiowania rekordów pozostawiała tabelę
`__c2c_battles_new`, mimo rollbacku, i blokowała następne uruchomienie migracji.

`_upgrade_activation_protocol_checks` wysyła teraz jawny `BEGIN` przed pierwszym
DDL. Istniejący context manager obejmuje rollbackiem cały batch przebudowy;
nie dodano osobnego destrukcyjnego cleanupu ani drugiej ścieżki migracji.

Parametryzowana regresja wstrzykuje błąd przy pierwszym kopiowaniu, usuwaniu
pierwszej tabeli, kopiowaniu drugiej tabeli i odtwarzaniu indeksu. Po błędzie
porównuje pełny schemat, rekordy, ustawienie FK i naruszenia FK. Następnie
sprawdza udany retry, idempotencję, brak tabel tymczasowych, zachowanie indeksu
i triggera oraz akceptację protokołu v3.

## Przeglądy i wpływ na wywołania

Wykonano dwa niezależne przeglądy read-only jako jawne odpowiedniki simplify
oraz code/security review; nie deklarujemy uruchomienia niedostępnych komend
slash. Obaj reviewerzy potwierdzili P2 i zaakceptowali gotowy fix oraz regresje.
W zleconym zakresie nie wskazali dalszych uzasadnionych zmian uproszczeń ani
dodatkowych P1/P2.

Call-site audit: helper jest wywoływany tylko przez `_migrate_schema`, a ta
przez `init_db` podczas bootstrapu aplikacji/skryptów. Poprawka nie zmienia
sygnatur, modeli, payloadów, klienta HTTP ani autoryzacji. Nie dodaje zapytań do
hot path requestów, indeksów ani nowego SSOT. V1/v2, jawny opt-in v3 i publiczne
fail-closed Oznaczenia pozostają bez zmian. JS/CSS nie edytowano, więc smoke UI
nie jest wymagany dla tego patcha.
